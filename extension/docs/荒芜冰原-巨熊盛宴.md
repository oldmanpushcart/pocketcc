## 0. 定位与体系

- **巨熊盛宴** = CQ26「寒霜系列 / 荒原冰原」（`series_frost`）里的 **BWL 线**（源码前缀 `SERIES_FROST_BWL_*`，控制器 `CQ26BeastData`，主面板 `CQ26BattleBeastMain*`）。
- 与同系列的 **NWL 线**（荒芜冰原分区采集 / 冰原巨兽挑战，前缀 `SERIES_FROST_NWL_*`）是**两条独立线**，仅在"融冰 / 奖励宝箱"上共用部分实体与小游戏协议。
- 世界地图入口：**巨兽据点** 实体 `313 CQ26_BEAST_BUILDING`；点击据点在 `feastPhase.state===2(FEED)` 时进入盛宴交互（融冰/礼盒），否则跳活动面板。
- 巨兽中心坐标本录实测 `{x:102, y:118, k:14002212}`（`k` 即世界房间 `wkid`）。

## 1. 活动阶段机（push 22032）

阶段枚举 `CQ26BeastFeastPhase`：`NONE=0 / GATHER=1（集结）/ FEED=2（喂养）/ SHOW=3（展示结算）/ END=4`。

`22032 SERIES_FROST_BWL_FEAST_PHASE_CHANGE` push 载荷 `feastPhase = {state, gatherTime, beginTime, endTime, displayEndTime}`。

**本录实测**（时刻为相对录制首行秒；游戏绝对秒戳见括号）：

| t        | state    | 含义                                                                                         |
| -------- | -------- | -------------------------------------------------------------------------------------------- |
| t+5199.8 | 1 GATHER | `gatherTime=1794234300, beginTime=1794234600, endTime=1794237600, displayEndTime=1794238200` |
| t+5499.8 | 2 FEED   | 同上时间轴不变                                                                               |
| t+8499.7 | 3 SHOW   | 进入展示/结算                                                                                |
| t+9099.8 | 4 END    | 盛宴关闭（`displayEndTime` 到点）                                                            |

- 窗口时长（绝对秒戳差）：GATHER `gatherTime→beginTime`=**300s**；FEED `beginTime→endTime`=**3000s**；SHOW `endTime→displayEndTime`=**600s**。
- GATHER 期：以融冰/点火推进**救援进度**，进度达阈值后解锁巨兽。
- FEED 期：解锁后进入喂养——领礼盒、抢巨熊宝藏、开奖励宝箱、喂养巨兽能量。
- SHOW/END：结算排名、关闭入口。

## 2. 玩法总览链路

```
[集结 GATHER]  融冰 2103 ──┬─ 直接奖励（火种）
                           └─ 旋转指针小游戏 2129（三温度档）
        全场融冰 → 救援进度 2102 累积 → 达 needUnlock 解锁巨兽 → 阶段转 FEED
[喂养 FEED]    盛宴礼盒 2106（index 0-9，逐个领，push 22075 发奖）→ 累加能量 blue
               巨熊宝藏 2108（地图随机落点，push 22064 通知；用户口语「巨熊宝藏」即此 2108）
               奖励宝箱 2104（地图共享宝箱，实体 315；本录未开）
               能量喂养：喂养值累加到 warzoneBeastInfo.blue，push 22044 实时播报 addBlue
[展示 SHOW]    排行 2107 / myRank 结算
```

## 3. 子玩法逐条（协议 + 源码判据 + 本录实证）

### 3.1 融冰 / 点火（2103 `SERIES_FROST_BWL_FIRE`）

- 源码 `CQ26WasteLandData.meltIce(e)`：需 `e.initSid===OriginServerId`、有冰模型、火种道具充足；`specIndex>0` 走 2117（NWL），**`specIndex===0` 走 2103（BWL）**。req `{x, y}`（无 wastelandIndex）。
- 消耗火种 `fireItemId`（配置 52000369 → 道具 **47007004**）；单次需求量读档表 52000359。
- resp `{isOk, rewardResult | miniGameId}`：
  - 带 `rewardResult` → 直接弹 `CommonRewardPanel`；
  - 带 `miniGameId`（≠"0"）→ 打开小游戏 `CQ26WLRemoveIceView`。
- **本录**：116 次融冰（req/resp 各 116，`isOk` 恒 1），坐标散布 **x∈[4,136]、y∈[14,234]**；**77 次**直接奖励（`items=[47007004×1]`）、**39 次**触发小游戏（带 `miniGameId`）。
- **冰格真相双通道**（游戏侧融冰候选源）：`901 resp.iceList`（本录 201 条非空）与 `10018 push.iceList`（151 条非空）增量，行形态 `{x,y,level,specIndex,initSid,v}`，**`k` 在 body 顶层不在行内**；`level=0` 表示已融（删格），`specIndex===0` 为 BWL 线、`initSid===OriginServerId`（本录全 3828）才可融。GATHER 期并集 **289 唯一格**。

### 3.2 急速解冻·旋转指针小游戏（2129 `SERIES_FROST_NWL_FIRE_MINI_GAME`）

- 源码 `CQ26WLRemoveIceView`：指针在温度条上旋转，**三段温度区**（index 0/1/2 = 低温 / 中温 / 高温… 档位），命中档给不同倍率；档间比例读配置 52000358（`o|a|i`）；10s 倒计时，超时给最低档。
- req `{id: Int64(=miniGameId), index}`，resp `{rewardResult}`。
- **本录**：39 次，`index` 分布 **{0:2, 2:37}**（绝大多数命中 index=2 档）；奖励 `items` 含 `47007004×2~3` 及 1700098 / 62908 / 62910 / 1988002 等。
- **代摇后必须复刻原生那两步：先开奖励面板、再收急速解冻窗**（实证 rec 11981629951662 / dashcam-rec-20261112T021006…-1794420606597）：
  面板 `UIDataInfo.CQ26WLRemoveIceView` 注册项写 `clickBlankClose:false`（点空白关不掉），而 `submitMiniGame` 的
  成功回调只在「游戏自己那一发」上跑；我们代发的 2129 结算后，视图的 `_submitting` 仍为 false、指针继续扫、
  10s 倒计时继续走。实录里玩家补了一下：同一枚 id 的第二发 2129 在 +8.8s 出网，撞回
  `header.s=3 / d=activity_120002`（字典表：「参数错误」），而 `NetMgr` 对外层 `s===3` 无条件
  `ShowTips(getNetMsgText(d))` ⇒ 奖励已到账却在玩家脸上弹一条错误。因此 `cq26IceShake` 成功结算后按原生
  同序走两步：`ui.open('commonRewardPanel', {serverReward: 应答.rewardResult})`（玩家要求能看见奖励；该视图
  自己的成功回调与 BagPanel/QuestController 等全仓都是这一个调用，面板注册项为
  `CommonRewardPanel=new e("rewardOutPanel",TYPE_POP,"ui",3,0,{frame:None,pauseGuide:!,hideMask:!,cacheUI:!})`）
  → `ui.close('iceShakePopup')`（`cpnDisable` 里的 `showTimeoutLowestReward()` 在当前 bundle 是空函数，无副作用）；
  奖励面板自身不自动关，由玩家自己点掉——它是正常游戏 UI，不是我们要抹掉的入口。
  若应答不带 `rewardResult`（或为空对象）则不开空窗，只进日志。且被在途闸挡下的那一发**不重投**（重投只会再制造一条 s=3）。

### 3.3 救援进度（2102 `SERIES_FROST_BWL_RESCUE_INFO`）

- UI `CQ26WLHelpBoss`：进度 = `rescueInfo.unlock / needUnlock`；4 个里程碑图标按 `getRemoveIceStageNeedCount(stage, needUnlock)` 点亮。
- req `{}` → resp `{rescueInfo:{unlock, needUnlock, total}}`。
- **本录**：`needUnlock=700, total=3500`；`unlock` 从 **3069 → 3249**（全场累计，早已越过解锁线）。

### 3.4 盛宴礼盒（2106 `FEAST_GET_GIFT` ＋ push 22075 `FEAST_GIFT_REWARD`）

- 源码 `CQ26BeastData.requestGetBattleBeastGiftBox(e)`：**仅 `feastPhase.state===FEED` 可领**；未加入派系弹 tips 跳 `CQ26TechView`；`hasGetBattleBeastGiftBox` 用 `_myFeastInfo.claimedIndexList.includes(idx)` 去重。地图实体 318 `CQ26_BATTLE_BEAST_FEAST_GIFT`，点击 → `requestGetBattleBeastGiftBox(index)`。
- req `{pointIndex}`（index 0-9，共 10 个礼盒位），resp `{}`（空，实际发奖走 **22075** push）。
- push 22075 载荷 `{pointIndex, blue, claimedIndexList, rewardResult:{items,…}}`——**奖励明细在 `rewardResult.items`，不在顶层 `items`**（feat 发奖日志只从 22075 读）。
- **本录**：18 次 req（`pointIndex` 序列 `9,9,0,0,0,6,6,2,4,7,8,8,0,0,1,2,3,5`）；22075 命中 10 个 index 全领完，每箱主奖励 **41142×500** + 2 项随机（47007004×10 / 38006601 / 69159 / 62908 / 62910 / 2801000 / 23044402 / 1700402 / 1700403 等）；每箱给能量 `blue` ∈ 2~6。
- **重试到成功是真值**：resp 空体、成功判 `header.s===0`；18 发原始 resp `s=0×10 / s=3×8`（按 rt 配对到 req 的成功 6 / 被拒 5 / 未配对 7）。同一 idx 被拒后重试合法——`idx=0` 序列 `[3,3,3,3,0]`（前 4 发撞 s=3、第 5 发才成功）；**每个 pointIndex 至多一次成功**（成功后不可重复领），这正是 feat 乐观集去重的依据。

### 3.5 巨熊宝藏（2108 `FEAST_GET_SECRET_GIFT` ＋ push 22064 `SERIES_FROST_SECRET_GIFT_LIST`）

- 源码：地图随机刷出的限时礼盒，实体 310 `CQ26_BATTLE_BEAST_FEAST_RANDOM_GIFT`。`clickCQ26BeastFeastRandomGiftBuilding`：`endTime>ServerTime` 时弹 `RandomRewardPop`（预览），到期后发 **2108** `{id: Int64.fromString, received:true}`；受日上限 `secretGiftCount >= 52000078` 与 `playerList.includes(StrUid)`（已领过去重）约束。
- push 22064 **全量快照**（整体替换本地表）：`gift:[{id:Int64, pos:{x,y,k}, endtime}]`（数组，含空表）。
- resp `{rewardId, receiveReward/items, playerInfo}`。
- **本录**：22064 全量快照 **41 条**（含空表；早期快照 40 条）、**20 枚唯一 id**；2108 req 12 次、**唯一 id 10 个**；resp `rewardId ∈ {52082911, 52082915}`（含 1 条 `rewardId=0` 的空回），产出 `47007005×5` 等。玩家快照 `secretGiftCount` 由 0 涨到 **5**。
- **领取时机实证**（绝对秒口径，rec 20261109T205818 / 20261113T224228）：礼物在自身 `endtime` 前 **~32s（周一）/~37s（今天）** 首现于 22064 快照；真人成功领取（s=0）集中在 `endtime` 当口（客户端录制 ts 距 end **-0.2~-6.8s**，系客户端 ts 与服务器 endtime 的 skew，非提前可领）。**10 槽共享抢夺**：310 地块 `playerList` 由 0 累积至 10、`maxPower=10`，槽满即从 22064 快照清除、再领撞 s=3。feat 取 **`grace=0` 到点即抢**：`nowSec(=DATA.ServerTime) >= endtime` 即发，与游戏点击闸 `endTime≤ServerTime` **完全同口径同一时钟**；并设 `endtime+600s` TTL 上限。整体替换本地表（镜像游戏 `updateSecretGiftList`），不保留已清除条目。

### 3.6 能量喂养（push 22044 `WARZONE_ICE_BEAST_INFO_CHANGE`）

- `warzoneBeastInfo = {faction, blue, maxBlue, level, state, summonCdEndTimeSec, currWorldId, currRoomId}`；每次喂养再带 `addBlue`（本次增量）。UI `CQ26BeastBaseBuilding.updateEnergyProgress` 进度条 = `blue/maxBlue`，`updateEnergyAdd` 飘 "+addBlue"。
- **本录**：22044 共 **629** 条；`warzoneBeastInfo` 形态恒 `{faction:1, blue:5200, maxBlue:5200, level:1, state:1, …}`（本服能量已满）；`addBlue` 分布 **{2:126, 3:135, 4:115, 5:134, 6:119}**（全服玩家持续喂养的实时播报）。

### 3.8 奖励宝箱（2104 `GET_CHEST` ＋ 2105 `OPENED_CHEST_LIST`，实体 315）

- **是什么**：散布在盛宴冰原上的**共享奖励宝箱**——由玩家融冰/开冰产出放置（`CQ26WLOpenIceComponent` 读表 `series_frost_small_wasteland.ice_place_reward`），同服玩家可轮流点开领奖。
- 地图实体 `pointType=315 CQ_26_WL_REWARD_BOX`；`m.specIndex===0` → BWL 线，走 **2104 BWL_GET_CHEST** `{x, y}` → resp `{rewardResult}`（`specIndex>0` 则 NWL，走 2118 `{wastelandIndex,x,y}`）。
- 已开去重：**2105 BWL_OPENED_CHEST_LIST** req `{}` → resp `{posList:[{x,y}]}`；新箱落点可经 push **22077 `WASTELAND_CHEST_POS_PUSH`** 通知。
- 领取闸门（`clickCQ26WLRewardBox`）：`extData.initSid===OriginServerId`（只开本服）且 `expireTime>ServerTime`（未过期）。
- 每人日上限：`wlInfo.remainChestNum`（push **22072 `SERIES_FROST_NWL_INFO_PUSH`** 权威）vs 配置 **52000426**；`leftTimes<=0` 或超上限 → tips `series_frost_wasteland_tips_042`。**BWL 盛宴奖励宝箱与 NWL 遗失之箱共享同一 `remainChestNum` 日额度**（源码 `onClickGetReward` 两分支都查它；本录 22072 轨迹 `5→4→3→2→1→0`）——feat 与 wl-chest 不做中央账本，各自每拍读 22072、串行出网，极端并发由服务器拒绝一方。
- 弹窗 `CQ26WLWorldRewardBoxPop`：名称串 `series_frost_wasteland_text_069`，图标 `icon_wl26_rewardbox`，含放置者名/联盟标签、到期倒计时、"领取"按钮、世界坐标分享链接（`sendChatLinkWorldSite`）。
- 宝箱地块 `p={pointType:315,x,y,k,v,m:{…}}`；`m` 字段：`remainTimes/leftTimes`（总/剩余可开次数，多人共享）、`specIndex`（**0=BWL 盛宴线 / 11=NWL 分区线**）、`uidList`（已开名单）、`playerInfo`（放置者 JSON）、`uid`、`a_name/a_tag`（联盟）、`initSid`、`itemId`（奖励包 id）、`expireTime`、`state`、`wSpecId`。**剩余次数实证拼写为 `leftTimes`**（本录 315 行 ×272 全如此，反编译源码 `CQ26WLWorldRewardBoxPop` 亦然；`lefftTimes` 笔误形态在本录与源码中均未出现，feat 仅留作防御回落）。
- **本录**：世界扫描（901/10018）见 315 地块 **272 行**——BWL(`specIndex=0`)×207 行 / **7 唯一坐标**（x 42–162、y 54–234），NWL(`specIndex=11`)×65 行 / 7 唯一坐标（归 wl-chest，本 feat 不抢）。BWL 箱全部由联盟「仙侠战歌」(`a_tag=38z8`, `initSid=3828`) 产出，`itemId=520827002`、`leftTimes=20`、`expireTime≈1794314661`（游戏时刻 +18h）；全程 `leftTimes` 恒 20、`uidList` 空 → **无人（含录制者）开过**，故 **2104=0、2105 回 `posList:[]`**。定稿后 **22077 宝箱落点推送出现 6 条**（早期快照为 0；载荷 `{pos:[{x,y,k}]}`，含 NWL 房间 `k=14002112` 与 BWL 房间 `k=14002212` 两批落点）。
